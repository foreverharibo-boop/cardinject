# CardInject

AI로 캐릭터 카드를 분석해서, 프롬프트의 알맞은 위치에 자동으로 주입해주는 SillyTavern 확장이야.

---

## 뭘 해주는 확장이야?

CardInject는 캐릭터 카드(설명, 성격, 시나리오, 예시 대화, 시스템 프롬프트, post-history instructions)를 읽어서 현재 연결된 AI에게 분석을 맡기고, 그 내용을 논리적인 카테고리로 나눠줘. 각 카테고리는 프롬프트의 서로 다른 위치에 주입돼서, AI가 항상 적절한 시점에 적절한 정보를 받을 수 있게 해줘.

---

## 설치

1. SillyTavern에서 **Extensions → Install extension** 이동
2. 저장소 URL 붙여넣기
3. Install 클릭

ZIP 패치본은 기존 설치 폴더를 삭제하지 않고, ZIP 안의 파일을 모두 덮어쓴 다음 SillyTavern 페이지를 새로고침해. `index.js`, `injection-runtime.js`, `hook-chain.js`, 새 `final-injection.js`, `manifest.json`을 함께 설치해야 해. 기존 `.git` 폴더는 유지해.

---

## 사용법

1. 캐릭터 채팅 열기
2. **Extensions → CardInject** 이동, 또는 확장 완드 메뉴에서 찾기
3. **AI로 캐시트 분석하기** 버튼 클릭
4. 분석 끝날 때까지 대기 — 카테고리 목록이 뜸
5. 필요하면 위치 조정하거나 카테고리 켜고 끄기
6. **주입 적용** 버튼 클릭

주입은 생성할 때마다 자동으로 다시 적용돼. 설정을 바꾸지 않는 이상 매번 다시 누를 필요 없어.

## 주입 위치

| 위치 | 어디에 들어가나 |
|---|---|
| 🔝 시스템 최상단 | 모든 것보다 위 — 메인 시스템 프롬프트보다도 앞 |
| 💬 최근 메시지 위 (depth 2) | 채팅 기록 내부, 마지막 2개 메시지 바로 위 |
| 📝 작가노트 | 전송용 작가노트 본문 뒤에 합쳐짐. 저장된 작가노트 원문은 유지 |
| 🤖 AI 응답 바로 직전 (최종 system 지시문) | depth 등록 없이 본답변 전송용 `messages` 맨 끝에 system 지시문 추가 |
| 🎛️ 특정 프리셋 프롬프트 앞/뒤 | 현재 불러온 Chat Completion 프리셋의 특정 프롬프트 바로 옆 — 드롭다운에서 선택 |

프리셋 프롬프트 목록은 현재 활성화된 프리셋에서 자동으로 불러와. 목록에 아무것도 안 뜨면 Chat Completion / OpenAI 호환 API를 안 쓰고 있거나, 프리셋에 커스텀 프롬프트가 없는 경우일 수 있어.

## 참고사항

- **캐릭터별 독립 저장**: 캐릭터마다 카테고리 목록이 따로 저장돼. 캐릭터를 전환하면 주입도 자동으로 그 캐릭터 것으로 바뀜.
- **작가노트 위치**: 작가노트가 비어있으면 CardInject가 정확한 위치를 못 찾아서, 작가노트 depth 설정값(기본 4)을 기준으로 실제 채팅 메시지만 세서 "작가노트가 있었다면 있었을 자리"에 근사 삽입해. 정확히 맞추고 싶으면 작가노트에 텍스트를 조금이라도 넣어두면 돼.
- 작가노트 depth가 **0**이면 마지막 메시지 뒤에 삽입해. 프리셋 대상이 꺼져 있거나, 최종 요청에서 대상 본문을 유일하게 찾지 못하면 해당 카테고리를 마지막 메시지 뒤에 보충하고 콘솔에 대체 위치를 알려줘.
- 캐릭터 시트 분석과 카테고리 재수집은 확장 탭에서 선택한 연결 프로필로 백그라운드 생성돼. 본채팅에 메시지를 추가하거나 현재 연결 프로필을 바꾸지 않아.
- 펼친 카테고리의 **Google 번역 보기** 버튼으로 한국어 번역본을 확인할 수 있어. 번역본은 화면 확인용이고 AI에게는 기존 원문만 주입돼.
- 분석된 내용은 캐릭터 이름을 그대로 쓰는 대신 `{{char}}`/`{{user}}` 매크로를 자동으로 사용해서, 스와이프하거나 캐릭터 이름을 나중에 바꿔도 정확하게 유지돼.
- 작가노트와 프리셋 상대 위치는 조립된 요청에 삽입하므로 SillyTavern 기본 프롬프트 미리보기에는 표시되지 않을 수 있어. 최종 전송 시 모든 활성 카테고리를 다시 확인해. 일반 위치는 이미 들어간 내용을 중복 삽입하지 않고, 최종 위치는 자기 요청별 주입을 별도로 확인해. 저장된 프리셋과 채팅 기록은 변경하지 않아.
- 본답변 요청이 `quiet`여도 실제 본생성 호출 경로와 현재 채팅 턴이 확인되면 주입해. 번역·분석·재수집의 보조 호출은 제외하며 요청의 모델, 프로필, `type`, 스트리밍 설정은 유지해.

## 1.0.5 최종 위치 추가

- 별도 Pro 없이 일반 CardInject에서 **AI 응답 바로 직전 (최종 system 지시문)**을 선택할 수 있어. 기존 캐릭터 분석·재수집·번역 보기·프리셋 앞뒤 삽입 기능은 유지해.
- 이 위치는 채팅 history의 depth 0이 아니야. 최종 fetch 처리에서 나머지 카테고리 처리를 끝낸 뒤 전송 메시지 맨 끝에 추가해. 역할은 `system`이고, `user` 지시문이나 assistant 프리필을 새로 만들지 않아. 같은 위치의 카테고리는 목록 순서로 묶어.
- 예전 ‘생성 직전 최하단’과 ‘AI 응답 바로 직전’은 같은 최종 위치로 처리해. 드롭다운에는 선택지 하나만 표시해. 저장된 `chat_bottom` 값과 customDepth를 재작성하지 않고 해석할 때만 호환 처리하며, 최종 위치에는 customDepth를 적용하지 않아.
- 이 옵션의 기존 자기 depth 등록값은 지워. 생성 시작 때 최신 설정을 반영해서 quiet 본답변에서도 이전 위치의 자기 등록값이 남지 않게 해.
- 다른 위치에 같은 본문이 있다는 이유로 최종 위치 주입을 생략하거나 그 본문을 삭제하지 않아. 전송 중 재검사는 요청별 소유 증거로 자기 최종 블록만 확인해 처리해. 증거가 손상되거나 모호하면 기존 내용을 보존하고 경고해. 소유 메타데이터는 HTTP JSON 본문에 들어가지 않아.
- 프리셋의 저장 순서·활성 여부·본문, 실제 채팅 기록, 다른 확장의 등록 ID는 변경하지 않아. CardInject의 저장 키와 표시 이름도 유지해.
- 이 위치의 보장 범위는 CardInject의 최종 전송 처리에서 만드는 `messages` 배열이야. 시스템 지시문을 별도 항목으로 분리하는 API에서는 모델 입력의 물리적 마지막 대화 위치와 다를 수 있어. 후속 외부 처리·서버 변환이나 모델의 지시 준수율까지 보장하는 옵션은 아니야.
- 일반 CardInject 설치 폴더에 업데이트하면 돼. 이 기능에 별도 CardInject Pro 설치는 필요 없어.

## 검수

소스와 배포 ZIP 압축 해제본에서 각각 자체 검사 18개와 별도 또또 동시 사용 검사 5개를 통과했어. 마지막 system 배치, 옛 최하단 별칭, 기존 depth 위치, 프리셋 앞뒤·작가노트, 조립 이벤트 이후 문구, 후속 fetch 래퍼, 동일 수동 문구·멀티모달·헤더·취소 신호 보존, Request 재전송, 일반/quiet/재생성/스와이프/계속 생성, 보조 요청 제외, 비활성화를 확인했어.

동시 사용 검사는 또또 1.12.8과의 두 로드 순서 및 WEAVE 프리셋 상대 위치/depth 0 조합마다 200회 본생성을 실행했어. 자체 최종 위치 검사에서도 후속 래퍼를 통과하는 본생성 200회와 소유 블록 재배치 200회를 확인했어. 기존 공통 주입 모듈·훅 체인·CSS와 또또 프롬프트 원문도 보존됐어.

이 검수는 코드와 모의 ST 요청 기준이며, 사용자 ST 서버에서 실제 모델 응답까지 생성한 검증은 아니야. 최종 전송 보충은 Chat Completion의 `/api/backends/chat-completions/generate`를 대상으로 해. 자체 테스트는 `npm test` 또는 `node --test tests/*.test.mjs`로 실행할 수 있어.

## 실제 전송 확인

브라우저 개발자 도구의 Console에서 `[CI] 전송 직전 카테고리 검사`를 확인할 수 있어. `requestPath`는 확인한 본생성 경로이고, `categories`에는 카테고리별 확인·삽입 결과가 나와. `fallback`이 비어 있지 않으면 일부 내용은 지정 위치 대신 대체 위치에 들어간 거야. 프롬프트 본문이나 대화 내용은 이 로그에 출력하지 않아.

실제로 보낸 내용은 **Network → 본답변의 `/api/backends/chat-completions/generate` → Payload → messages**에서 확인해. 번역기도 같은 주소를 쓰므로 번역 요청과 본답변 요청을 구별해야 해. 콘솔 로그만으로 서버 수신까지 확정할 수는 없어.

## 프리셋과 다른 확장

- 프리셋의 `prompts`와 `prompt_order`는 읽기만 해. 저장된 순서, 활성 상태, 내용은 재정렬하거나 저장하지 않아. 위치 선택은 전송용 메시지에 CardInject 내용을 추가하는 데 사용돼.
- CardInject와 또또의 전송·매크로 관찰 훅은 서로의 연결을 인식해 반복 생성마다 쌓이지 않아. 다른 확장의 전송 함수는 그대로 호출해.
- 초기화와 비활성화는 `cardinject_` 이름의 주입 항목만 정리해. 비활성화한 훅은 요청을 그대로 넘기며 다른 확장의 연결을 제거하지 않아.
- 같은 기준 프롬프트에 여러 확장이 주입하면 확장 실행 순서에 따라 추가 내용 사이의 순서가 달라질 수 있어. 기존 프리셋 항목의 저장 순서는 바뀌지 않아.

다른 확장이 프리셋을 직접 바꾸거나 전송 처리를 통째로 대체하는 경우까지 막는 기능은 아니야.
